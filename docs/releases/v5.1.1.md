# RedlineDB v5.1.1

> **Experimental release.** RedlineDB uses its own database format, its C ABI
> implements only an experimental subset of `sqlite3_*`, and its PostgreSQL
> program checks SQL-shell transcripts rather than a wire protocol. Back up
> databases before upgrading. `Strict` durability claims process-crash
> survival on the measured filesystem, not power-loss or operating-system
> crash survival.

v5.1.1 fixes a row-loss bug in automatic rowid allocation and reduces work on
common write and indexed-read paths. The on-disk format, index-format epoch,
and C ABI major version are unchanged from v5.1.0. Databases written by v5.1.0
open without a migration, but applications that relied on the old global
rowid numbering will observe different automatically assigned values.

## Changes that can affect you

- **Automatic rowids are per table.** Each table now starts its own sequence
  at 1. Previously, all tables shared a counter. A `DELETE` of the highest
  `INTEGER PRIMARY KEY` in one table could lower that shared counter, so the
  next insert in a different table could reuse a live rowid and silently
  replace its row. The same correction gives `last_insert_rowid()` and NULL
  `INTEGER PRIMARY KEY` inserts the per-table values SQLite assigns.
- **Rolled-back deletes do not reuse live keys.** A delete of the highest
  key followed by rollback no longer gives the next NULL-key insert a key
  still held by the restored row. This also prevents `REPLACE` from silently
  replacing that row.
- **Concurrent writes protect rowids.** An explicit-key insert or key-moving
  update now locks the rowid. A key committed after a transaction's snapshot
  produces a serialization conflict; autocommit retries and then applies
  the statement's normal conflict action. NULL-key and `AUTOINCREMENT`
  inserts step past keys being written by another connection.
- **Concurrent schema changes serialize.** A schema change holds its schema
  lock until the transaction ends, preventing two transactions from assigning
  the same internal table id and losing one table.

## Engine work

- An `INTEGER PRIMARY KEY` conflict check probes the named rowid instead of
  scanning the table. Deleting a row scans for a new maximum only if that row
  held the table's highest rowid; `AUTOINCREMENT` keeps its counter.
- Indexed equality and range reads can project the row loaded for index
  visibility recheck, avoiding a second relation read for matching rows.
  The loaded-row buffer is bounded and falls back to rowids for broad scans.
- Statements create their spill directory only when they actually spill.
  Unpinning a buffer page no longer wakes threads that cannot be waiting
  on the page. The buffer pool rechecks freed capacity before reporting a
  full-pool pin failure.
- The kernel exports buffer, directory and WAL work counters used by the
  performance regression gates. These counters are observational and do not
  change database behavior.

when the release evidence is accepted. A process crash is the measured fault;
this is not a power-loss claim.

## Known limitations

`sqlite_sequence` is not yet kept across a reopen. An `AUTOINCREMENT` table can
therefore reuse a rowid that was deleted before that reopen. The remaining
known SQLite failures and other limits are described in the generated README
reports and [v5.1.0 notes](v5.1.0.md#known-limitations).

## Verify your download

Each archive has a SHA-256 sidecar and a build-provenance attestation naming
this repository, tag and commit.

```bash
VERSION=v5.1.1
PLATFORM=linux-x86_64   # or linux-arm64, macos-x86_64, macos-arm64
ASSET=redlinedb-$VERSION-$PLATFORM.tar.gz
BASE=https://github.com/neverhuman/redline/releases/download/$VERSION
curl -fsSLO "$BASE/$ASSET"
curl -fsSLO "$BASE/$ASSET.sha256"
sha256sum -c "$ASSET.sha256"        # macOS: shasum -a 256 -c "$ASSET.sha256"
gh attestation verify "$ASSET" --repo neverhuman/redline
```

```bash
curl -fsSL https://raw.githubusercontent.com/neverhuman/redline/v5.1.1/install.sh | VERSION=v5.1.1 bash
~/.local/bin/redlinedb --build-info --json
~/.local/bin/redlinedb -batch :memory: 'SELECT 1;'
```

# RedlineDB v5.1.0

Released 2026-09-29; the `v5.1.0` tag names the source commit.

> **Experimental release.** RedlineDB is not a replacement for SQLite. It uses
> its own file format, its C ABI is an experimental subset of `sqlite3_*`, its
> PostgreSQL support is a SQL-shell corpus with no wire protocol, and its
> durability claim covers a process crash in `Strict` mode, not power loss.
> Read [Known limitations](#known-limitations) before you upgrade.

v5.1.0 brings the `redlinedb` shell and RedlineDB's error text in line with
the sqlite3 3.53.1 shell. Most sqlite_parity cases that v5.0.0 published as
known failures now pass. The database file format, the index-format epoch
and the C ABI (`libredlinedb.so.5`) are those of v5.0.0, and v5.1.0 opens
v5.0.0 databases as they are. What changes is text: error messages and some
shell output, so tools that match
RedlineDB's old wording need updating (see
[Changes that can affect you](#changes-that-can-affect-you)).

## Highlights

- **SQLite's error text.** A statement SQLite rejects now fails with
  SQLite's own message, in the shell and from `sqlite3_errmsg`:
  `no such table: t`, `table t already exists`, `UNIQUE constraint failed:
  t.a, t.b`, `cannot start a transaction within a transaction`,
  `near "X": syntax error`, `incomplete input`, `no such function: f`,
  `misuse of aggregate function sum()`, `sub-select returns 2 columns -
  expected 1`, and `attempt to write a readonly database` (with
  SQLITE_READONLY) for a write under `PRAGMA query_only`. Error codes keep
  their classes; a missing table is still `NotFound` / `RLDB_NOTADB`.
- **The shell reads scripts as sqlite3 does.** Input runs one line group at a
  time. A failed group is reported as `Parse error near line N: ...` or
  `Error near line N: ...`, and the script goes on unless `-bail` or
  `.bail on`; the exit code is 1 once anything failed. SQL given as
  command-line arguments still stops at its first failure.
- **Shell output.** BLOBs print their own bytes; `-escape ascii|symbol|off`
  applies to TEXT and BLOB values, with `^X` for control characters by
  default; csv and tabs quote by sqlite3's rules. `.schema`, `.dump`,
  `.fullschema`, `.parameter list`, `.dbconfig`, `.show`, `.clone` and
  `.crlf` print what sqlite3 prints. `.connection` has real connection
  slots, `.sha3sum` computes sqlite3's SHA3 content hash, `-memtrace`
  reports RedlineDB's allocations, and `-readonly` opens a 0-byte file as an
  empty read-only database.
- **SQL.** `ALTER TABLE ... ADD COLUMN` accepts a CHECK constraint, tests it
  against the rows already stored, and splices the column into the table's
  stored `CREATE TABLE` text as SQLite does. `RAISE()` outside a trigger is
  refused. A `CASE ... END` expression inside a trigger body no longer ends
  the body.

## Changes that can affect you

- **Error text.** Code or tests that match RedlineDB's old messages, such as
  `kernel error: object not found`, `unsupported function f`, `transaction
  state error: ...` or `unknown table: ...`, see SQLite's wording instead.
  Match on error codes where you can.
- **Shell errors and scripts.** Shell errors no longer carry RedlineDB's
  numeric code and category (`Error: 12: kernel error: object not found`
  becomes `Parse error near line 1: no such table: t`). A script read from
  stdin or `.read` no longer stops at its first error; pass `-bail` to stop.
- **`.shell` and `.system` run commands.** In v5.0.0 they imitated `printf`.
  Any script the shell reads (stdin, `.read`, `-init`) can now start
  processes, as in sqlite3. Run untrusted scripts with `-safe`, which
  refuses them.
- **Control characters.** TEXT values print control characters as `^X` in
  list, csv and tabs output by default, as sqlite3 does; `-escape off`
  prints them raw.

## Known limitations

- **Still-listed SQLite cases.** `metadata/sqlite_parity/known-failures.json`
  lists the cases that still fail, each with its reason: `EXPLAIN` bytecode
  (RedlineDB has no VDBE), `.auth`, `.expert` and `-interactive`, which could
  only pass on output RedlineDB does not compute, and `-pcachetrace`, which
  traces nothing yet.
- **Table text after other ALTERs.** `RENAME TO`, `RENAME COLUMN` and `DROP
  COLUMN` rebuild a table's stored `CREATE TABLE` text without its CHECK and
  UNIQUE clauses. They are still enforced, but `.schema` and `.dump` do not
  show them.
- **Shell details.** `.mode` resets `.headers` to the mode's default, where
  sqlite3 keeps it; a CHECK failure names the table, not the constraint; a
  few errors sqlite3 reports while preparing are labelled `Error near line`
  rather than `Parse error near line`; `RAISE()` outside a trigger is refused
  when it is evaluated, not when the statement is prepared.
- **Everything v5.0.0 lists** under
  [Known limitations](v5.0.0.md#known-limitations) still applies, except the
  shell stopping at its first stdin error.
- The README's version table was not measured again for this release; its
  latest row is v5.0.0. No performance change is claimed.

## Verify your download

Each archive has a `.sha256` file, build provenance that names this repository
and tag, and a GitHub build provenance attestation.

```bash
VERSION=v5.1.0
PLATFORM=linux-x86_64   # or linux-arm64, macos-x86_64, macos-arm64
ASSET=redlinedb-$VERSION-$PLATFORM.tar.gz
BASE=https://github.com/neverhuman/redline/releases/download/$VERSION
curl -fsSLO "$BASE/$ASSET"
curl -fsSLO "$BASE/$ASSET.sha256"
sha256sum -c "$ASSET.sha256"        # macOS: shasum -a 256 -c "$ASSET.sha256"
gh attestation verify "$ASSET" --repo neverhuman/redline
```

Install and smoke test (`REDLINEDB_VERIFY_ATTESTATION=1` makes the installer
run the attestation check too):

```bash
curl -fsSL https://raw.githubusercontent.com/neverhuman/redline/v5.1.0/install.sh | VERSION=v5.1.0 bash
~/.local/bin/redlinedb --version                 # prints redlinedb v5.1.0 (tested against SQLite 3.53.1)
~/.local/bin/redlinedb --build-info --json       # names the tag and commit
~/.local/bin/redlinedb -batch :memory: 'SELECT 1;'   # prints 1
```
